Patch Tuesday Brief

November 2026 Security Updates

What Microsoft and Adobe actually released on November 10, the handful of fixes that matter, and what the updates are known to break.

Brief published November 10, 2026 · Breakage watch updated November 28, 2026

1,094 fixes in Microsoft's November release, the second huge month in a row after October's record 1,413
1 bug already being exploited this month, in Microsoft Outlook, and it is the one to patch first
110 fixes from Adobe across nine products, none known to be exploited yet

The release at a glance

Every Patch Tuesday ships hundreds of fixes. This table is the whole month on one screen: who released what, how bad the worst bug is, and whether attackers are already using any of it.

Microsoft's release carries 1,094 CVEs by our count from the Security Update Guide; the Zero Day Initiative counted about 1,090 in its November 2026 review of the same release. Either way, it is the second month in a row above every previous year.

The ones that matter

Out of 1,094 Microsoft fixes, these are the ones a small business or its IT provider should care about this month, worst first.

CVE-2026-124194CVSS 6.5

Microsoft Outlook flaw, already being exploited

The score looks modest, but this is the one bug attackers are using right now. A booby trapped message file makes Outlook quietly connect to an attacker controlled location and hand over a credential hash, which the attacker can then use to log in as that user. CISA added it to the Known Exploited Vulnerabilities catalog on release day and gave federal agencies until November 24, 2026 to patch.

What to do: push the November Office and Outlook updates first, ahead of everything else this month.

CVE-2026-116928CVSS 9.8

Windows Search flaw reached through Exchange mail

An attacker emails a specially crafted attachment, the mail server indexes it automatically, and code runs on the server. Nobody has to open anything. It is the most severe server bug this month, worse than the fixes written specifically for Exchange.

What to do: if you run your own Exchange server, patch it this week, not at month end.

CVE-2026-119958

Windows LDAP flaw, dangerous on domain controllers

An unauthenticated attacker can send crafted LDAP calls over the network and run code in the LDAP service, with no user interaction. On a domain controller, the server that decides who can log in to everything, that is about as bad as it gets.

What to do: domain controllers go near the top of the patch order, right after the Outlook fix.

CVE-2026-118207

Exchange Server remote code execution

One of nine Exchange fixes this month, rated Critical, delivered in update KB5133453. On premises Exchange is a favorite attacker target because it faces the internet and holds every mailbox.

What to do: patch Exchange this week. If web mail or mail flow has been flaky since the October updates, check the breakage section below.

CVE-2026-96092

Windows DNS Server flaw on Server 2025

Part of a small set of DNS fixes this month that researchers class as wormable: unauthenticated, over the network, no user interaction. DNS servers are easy to forget because they just sit there working.

What to do: include your DNS servers in the first patch wave, especially Server 2025.

CVE-2026-119952

Windows Schannel flaw, exploitation rated more likely

Schannel is the part of Windows that handles secure connections. Microsoft rates this one Exploitation More Likely, one of only a few Critical fixes carrying that label this month, even though the attack is rated complex.

What to do: it rides in the normal Windows cumulative update, so no special handling, just do not defer the November updates.

Update breakage watch

What recent updates are known to break, checked daily against Microsoft's release health pages and credible admin reports. Confirmed items only, with the workaround where one exists.

November update KB5132061 install failure (resolved)

Affects: Windows 11 24H2, 25H2, and 26H2 after KB5132061. Install failed with 0x800f0993, 0x800f0989, or 0x80070306. Microsoft confirmed it as a known issue on November 11. Only machines that installed the October preview KB5127936 were affected.

Microsoft marked the issue resolved on November 16. The automatic repair ran on affected devices through Windows Update, no new package was needed. A machine that still fails to install after that repair is past the automatic fix.

What to do: if the install still fails, contact Microsoft Support. DISM or a manual .msu download are reported as alternates.

November updates crash Sage 50 US when opening a transaction window (fixed)

Affects: Sage 50 US 2026 and 2021 on Windows 10 and Windows 11, and Windows Server 2016 through 2025, after KB5132061 (Win 11), KB5132059 (Win 11 26H1), KB5131096 (Win 10), KB5131087 (Win 11 23H2), or the Server KBs KB5131077, KB5131079, KB5131080, KB5131090, KB5131085, KB5131291, and KB5131083.

Sage released a hotfix for Sage 50 US 2026.2 (build 33.2.00.0234) on November 20, and Microsoft's optional preview update KB5132057 for Windows 11 25H2 and 26H2, released November 19, also lists a fix for Sage 50 closing unexpectedly. Sage says Microsoft has acknowledged the issue and plans its own fix. The hotfix installs through Services, Check for Updates, Check Now, and it is a silent update, so close and reopen Sage 50 three times to make sure it downloads fully. If you use Quantum or Quantum Accountants Edition, stop the SmartPosting service first or the hotfix will fail. Older Sage 50 versions, and machines without an active Business Care plan, cannot get the hotfix and should keep delaying the Windows update until Microsoft ships its fix. Sage 50 Cloud (hosted) has a fix in place, so Cloud users should log out and back in. Do not uninstall or reinstall Sage 50 itself. Source: Sage KB article, updated November 20, 2026; Microsoft KB5132057 release notes.

What to do: install the Sage hotfix first through Check for Updates on Sage 50 2026.2, and close and reopen Sage 50 three times. You can then reinstall the November Windows update if you removed it. If the update cannot be uninstalled, roll back with System Recovery. If printing breaks after the uninstall, reinstall the printer. Sage 50 Cloud users should log out and back in to pick up the Cloud fix.

Activation commands failed after the November updates (fixed)

Affects: Windows 11 23H2 after KB5131087, Windows 10 after KB5131096, Windows Server 2025 after KB5131080, Windows Server 2022 after KB5131090, and Windows Server 2019 and Windows 10 LTSC 2019 after KB5131085. The activation commands slmgr.vbs /skms-domain and /ipk failed with error 0x80041008. Machines that were already activated stayed activated.

Microsoft released optional out-of-band cumulative updates on November 13 fixing it: KB5136483 (Windows 11 23H2) and KB5136489 (Server 2025), plus packages for Windows 10 21H2/22H2 and Server 2019/2022. They are cumulative, so they also carry the November security content. Source: Microsoft Message Center MC1551898, via Neowin Nov 13.

What to do: pull the fix from the Microsoft Update Catalog, it does not sync to WSUS or Configuration Manager, and deploy it by hand through your management tool. Windows 11 23H2 also shows it under Windows Update, Optional updates. Do not wait for WSUS to deliver it, it will not arrive that way.

Citrix MCS image preparation fails to rearm Windows (fixed)

Affects: Citrix Machine Creation Services image preparation on master images running Windows Server 2019 after KB5131085, Server 2022 after KB5131090, or Server 2025 after KB5131080, and also Windows 11 23H2 after KB5131087 and Windows 10 22H2 after KB5131096. Image preparation fails at the Windows rearm step, so the updated master image cannot deploy. Windows 11 24H2, 25H2, and 26H2 after KB5132061 are not affected.

Citrix confirmed on November 17 (article CTX697347) that this is the same licensing change Microsoft made for CVE-2026-96300: the Software Licensing WMI provider rejects the client machine ID query that MCS image preparation makes before it rearms Windows, failing with error 0x80041008. It is not caused by Citrix, and no change in MCS will make the rearm succeed while the issue is present. Microsoft fixed it in the November 13 out-of-band updates: KB5136490 (Server 2019), KB5136487 (Server 2022), KB5136489 (Server 2025), KB5136483 (Windows 11 23H2), and KB5136493 (Windows 10 22H2). Source: Citrix CTX697347.

What to do: install the matching November 13 out-of-band update on the master image, shut it down, take a new snapshot, and update the machine catalog, then confirm the catalog update completes without the rearm warning. Until then, keep using a pre-November snapshot. Pull the fix from the Microsoft Update Catalog, it does not sync to WSUS or Configuration Manager.

SQL Server linked server connections may stay open

Affects: SQL Server on server devices after the October 13, 2026 updates and later updates. Linked server queries to external databases, with Oracle and PostgreSQL named, may leave connections open instead of closing them.

What to do: a mitigation is available through Microsoft Support for Business. Microsoft now says the fix is planned for a future Windows update, so do not expect a quick out-of-band update. Deploy with this in mind if you run SQL Server linked servers.

Printing can fail after the November updates

Affects: Windows 10 and later, and Windows Server 2016 and later, after the November 2026 security updates. Printing can fail for documents containing images rendered with zero height or width at the selected print resolution. Confirmed in Word via GDI; other apps may be affected. The images can be invisible ones, such as watermarks or layout anchors from document-generation tools, so the user does not need to have added a picture. Microsoft is investigating (alert WI1549472; BleepingComputer and The Register, Nov 12-13).

What to do: no permanent fix yet, but there is a workaround: remove zero size images from the document, such as a watermark, or export the document to PDF and print the PDF instead. Keep the security update installed, and watch for a Microsoft fix.

Hotpatch KB5132043 can stop the Print Spooler

Affects: Windows 11 24H2, 25H2, and 26H2 after the November hotpatch KB5132043. The Print Spooler service stops, installed printers show as "Not connected", and nothing prints, including Print to PDF. Reinstalling printer drivers does not help. Uninstalling KB5132043 and restarting restores printing. Microsoft confirmed in a service alert on November 20 (reported by BleepingComputer on November 23) that the hotpatch can stop the spooler on devices running Forcepoint DLP Endpoint Agent: the print option can be greyed out, or selecting a printer can error, because the spooler fails to start. Spooler crashes on machines without Forcepoint are still not listed as a known issue by Microsoft (Neowin, Nov 17; Microsoft Q&A threads).

What to do: if your machines run Forcepoint DLP Endpoint Agent, Forcepoint has a temporary workaround for its customers through its support portal (sign in required). Otherwise, hold KB5132043 on machines that print, or uninstall it temporarily if printing already broke, then install the standard November cumulative update KB5132061 and restart, which admins report restores printing. No permanent fix yet. This is separate from the zero size image printing issue above, which hits documents rather than the spooler itself.

November hotpatch KB5132043 can stop Office and other apps from launching

Affects: Windows 11 24H2 and later devices that installed the November hotpatch KB5132043 through Windows Autopatch. Office and third party apps can fail to install, launch, or run, showing error 0xC0000099. Microsoft says it hits apps that load the 32-bit Windows Installer library, msi.dll, most often 32-bit apps, but 64-bit apps can be hit too. Devices on the standard November cumulative update KB5132061 are not affected. Microsoft confirmed it on November 19 in service alert WI1559710 (BleepingComputer, Neowin, The Register).

This also explains the Citrix Workspace App (LTSR) launch failure reported November 17, where an admin traced the failure to msi_hotpatch.dll in the same hotpatch. That report is now covered by this Microsoft-confirmed issue.

What to do: Microsoft's workaround is a registry change: back up the registry, then set HotPatchTableSize to 2000 under HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Memory Management, and restart the device. No permanent fix yet. If you deploy through Altiris rather than Windows Autopatch, your machines should not have the hotpatch, but check any Autopatch-enrolled devices.

November updates can break sign in through some NTLM proxies and single sign on tools

Affects: Windows 11 23H2, 24H2, 25H2, 26H1, and 26H2, Windows 10 Enterprise LTSC 2021, and Windows Server 2016 through 2025 after the November 10, 2026 security updates. Sign in can fail through third party authentication proxies, single sign on (SSO) products, and application packaging tools that use NTLM. Microsoft confirmed it on November 25 in support article KB5135557 (BleepingComputer, Nov 25). The November updates are the first phase of tighter NTLM message signing, a fix for the RPC Runtime flaw CVE-2026-118737, and some third party products do not implement NTLM correctly, so Windows now rejects their sign in attempts. Fortinet has already confirmed its Single Sign On Mobility Agent with FortiAuthenticator is affected, and Omnissa App Volumes agents have also been reported failing after the November updates. Microsoft plans phase 2 for May 2027, when Windows servers will start requiring NTLM signing by default and will reject clients that do not offer it, so any workaround has a deadline. This is separate from the October NTLMv1 enforcement change that can break office Wi-Fi, listed below.

What to do: no permanent fix yet. As a temporary workaround, Microsoft says to set the ClientAllowUnsignedNtlm registry value to 1 under HKLM\SYSTEM\CurrentControlSet\Control\Lsa\MSV1_0 on affected clients, but that weakens the relay protection the update added and Microsoft says the setting may be removed in a future update. The long term fix is to switch the affected product to Kerberos where possible, or ask the vendor for an update that meets the new NTLM signing requirements. Plan around May 2027, when Windows servers start requiring NTLM signing by default, so the registry workaround is not a long term answer. Deploy with this in mind if you use a third party proxy or SSO product in the sign in path.

November update can leave some PCs unable to boot (0xc0000001)

Affects: Windows 11 24H2, 25H2, and 26H2 after KB5132061, mostly on machines that also installed the October preview KB5127936. The PC stops at a blue Recovery screen with error 0xc0000001, or loops through Automatic Repair, and Startup Repair says a recently serviced boot binary is corrupt. Microsoft has not listed this as a known issue. The pattern in admin and repair shop reports points to the October preview change that automatically turns on memory integrity on supported PCs: an old CD and DVD burning driver, PxHlpa64.sys version 3.01.01.0, cannot run under memory integrity and can block the boot. The same failure has also been reported on machines without that driver, where turning virtualization off in the BIOS let Windows start again. Sources: Microsoft Q&A thread with several independent reports; Shibukawa PC Support, November 24-25; WindowsDigitals guide, November 27.

What to do: if a PC will not boot after the November update, turn virtualization (Intel VT-x or AMD SVM) off in the BIOS to get Windows started, then disable the old driver with sc config PxHlpa64 start= disabled from an elevated command prompt, restart, and turn virtualization back on. If BitLocker is on, have the recovery key ready before using the recovery screens. Check whether PxHlpa64.sys is present before applying that step, and remove old disc burning software that installed it. Hold the update on machines that still run old burning software until you have checked for the driver.

November updates break WordPerfect macros and PerfectScript (fixed in the November preview)

Affects: WordPerfect Office, including WordPerfect 2021, on Windows 10 and Windows 11 after the November 2026 security updates (KB5132061 on Windows 11, KB5131096 on Windows 10). Macros stop working, and the 32-bit COM/OLE link between WordPerfect and PerfectScript breaks. AskWoody flagged it on November 24, and WordPerfect users report the same failure in the WordPerfect Universe forum. It looks like the same underlying 32-bit COM/OLE problem behind the Sage 50 crash above.

What to do: users report the optional preview update KB5132057, released November 19 for Windows 11 25H2 and 26H2, restores macros. Install it through Windows Update, or wait for the December cumulative, which will carry the same fix. On Windows 10, pause KB5131096 until the December update if macros are business critical. The issue has also been reported to Corel.

November update breaks Dentrix Continuing Care (fixed in Dentrix 26.32)

Affects: Dentrix on workstations after KB5132061. Opening the continuing care section of a patient chart through the Family File application fails with "Unable to load Continuing Care Data". AskWoody reported it on November 24, and Dentrix lists the fix in its November 19 release notes: after a Windows update was installed, Continuing Care would not open, fixed in Dentrix version 26.32.

What to do: update Dentrix to version 26.32. If you run the latest Dentrix version, there is also a toggle to switch to the new continuing care interface as a workaround. No Windows-side fix is needed.

November Server hotpatch could crash Windows Server 2025 (fixed in KB5138318)

Affects: Windows Server 2025 devices enrolled in hotpatch updates after the November security hotpatch KB5131077, with Router Advertisement enabled and receiving time-bound IPv6 routes. The server could stop unexpectedly with stop error 0x139 (KERNEL_SECURITY_CHECK_FAILURE) when a route timer expired, which could be long after the patch was installed.

Microsoft released the out-of-band hotpatch KB5138318 on November 25, 2026, fixing it. It installs automatically through Windows Update on hotpatch-enrolled servers and takes effect without a restart. Source: Microsoft KB5138318; BleepingComputer and The Register, November 26-27.

What to do: check that KB5138318 is installed on hotpatch-enrolled Server 2025 machines, and check event logs for past 0x139 crashes to see if you were hit. No restart is needed. Machines not enrolled in hotpatch, and servers without Router Advertisement and time-bound IPv6 routes, are not affected.

October updates can break office Wi-Fi and wired network logins

Affects: Windows 11 24H2, 25H2, and 26H2 after KB5127648. The October update turned on a stricter sign in rule (NTLMv1 enforcement). Networks that log users in with the older MS-CHAPv2 method, common for office Wi-Fi, can start refusing connections. Home Wi-Fi with a plain password is not affected. Microsoft confirms the change is intentional hardening, so no fix is coming.

What to do: if office Wi-Fi breaks after the October update, your IT provider can roll the setting back to audit mode, or better, move the network to certificate based sign in (EAP-TLS).

October Server updates can stall on premises Exchange

Affects: Exchange 2016, 2019, and Subscription Edition on Server 2016 to 2025 after the October 13 updates. Sign ins to web mail can fail, mail can sit in the Outbox, and mailbox database copies can stall, starting about a day after a restart. Microsoft confirms the cause: a new limit on a lookup service Exchange leans on.

What to do: fixed in the November Server updates. The registry workaround is no longer needed once those are installed.

Some USB audio devices stopped working after the September and October updates

Affects: USB Audio Class 1.0 devices (some headsets, docks, and conference gear) on Windows 10, Windows 11, and Server. The device fails to start and shows error Code 10.

What to do: fixed in KB5132061 and KB5131096. Install the November update; the 2 channel mode workaround is no longer needed.

Always On VPN connection bug: fix is in the November updates

Affects: Always On VPN on Windows 11 24H2 and later, broken by the September updates and stuck on Connecting.

What to do: fixed on all branches in KB5132061. Install the November update, then the single protocol pinning workaround can be reverted.

Fixed in the November cumulative: Smart App Control and Remote Desktop

Affects: Smart App Control toggle grayed out, fixed for 24H2 in KB5132061; Remote Desktop failures for non-admin users (0xC000000D), fixed in KB5132061.

What to do: install the November update. No workaround needed after that.

Watch item, not confirmed breakage: KB5132061 tightens PowerShell script signature validation, so signed scripts with invalid UTF-8 may now fail validation. The November cycle now has thirteen confirmed breakage issues above.

Worth knowing

Notable fixes and campaigns that sit outside the exploited list but can still bite a small shop.

CVE-2026-83844

Microsoft Paint flaw with a patching gotcha

A serious flaw in the Paint app bundled with Windows, disclosed October 13. It is not being exploited and CISA has not listed it, but the fix only ships through the Microsoft Store, never through Windows Update. Shops that block the Store, or never open it, will stay unpatched without noticing.

What to do: make sure Store apps are set to update, or push the Paint update through your management tool.
